## 二、T01 分析运行版本与失效

### 新增契约
- `schemas/run.py`
  - `RunStatus = planned | executed | published`
  - `RunManifest`：`run_id / bundle_id / status / snapshot_hash / dictionary_hash /
    metric_spec_version="v1" / scope_hash / plan_hash / created_at / published_at`
  - `RunPointer`：active/current 双指针内容（run_id/bundle_id/updated_at）。

### 存储布局（storage.py）
```
<bundle>/
  active.json                 # 最新工作流运行（规划即前进）
  current.json                # 最近一次成功发布的仪表盘
  runs/<run_id>/
    manifest.json             # 运行指纹
    bundle.json               # plan_hash = 该文件 sha256
    execution.json
    dashboard.json
    views/<view_id>/…
    probes/<probe_id>/…
```
- `write_bundle`：分配 `run_<uuid12>`；snapshot_hash 取 quality 工件记录值，
  dictionary_hash 实时计算；active 指针 `os.replace` 原子切换。
- `execute_bundle` 前校验 manifest：bundle_id 不符 / 当前快照 hash 已变 → `StaleRunError`。
- `write_dashboard(..., expected_run_id=...)`：迟到合成若发现 active 已前进，拒绝回切 current。
- `synthesize_dashboard`：
  1. 校验 snapshot_hash / dictionary_hash / execution 存在；任一不符 `StaleRunError`；
  2. **幂等**：该 run 已发布过 dashboard.json 则直接读回，probe 预算不重置；
  3. 发布时原子写并更新 current。
- 路由：`POST analysis-bundle/execute`、`POST/GET dashboard` 统一把 `StaleRunError` 映射 409，
  detail 为中文操作指引（重新规划→执行→合成）；GET dashboard 在 active≠current 时 409，
  无 current 时 404。

### 兼容性
- 旧扁平布局的历史会话读 active 指针视为"无 bundle"，不会错读旧文件（预期失效）。
- `ViewExecutionResult.run_id`、`DashboardArtifact.run_id` 默认空串，旧 JSON 可解析。

## 三、T02 质量处理保护业务信号

- `FieldProfile` 新增 `metric_spec`（旧 JSON 缺省为 None，兼容）。
- 缺失值：数值/分类默认动作均为 `keep`（分类新增 `fill_unknown="未知"` 桶，仅用户显式选择时使用）。
- 离群值：建议集合收敛为 keep/mark；
  - 合法负值字段（利润/profit/亏损等，`_ALLOW_NEG_RE`）→ mark 保留；
  - 未授权负值 → mark 待人工确认；任何自动路径都不会产出 exclude。
- 重复行：建议改 keep，文案要求按业务键确认，不再默认删行。
- `apply_decisions` 在 `QualityReport.impact` 记录
  `rows_before/after、imputed_cells、dropped_breakdown、totals_before/after/total_deltas、
  fact_changing_actions`，事实改变动作（删行/插补/去重）可审计。
- 演示脚本（run_bundle_demo / run_dashboard_demo）改用 `safe_demo_decisions`：
  仅格式转换（如日期/数值 convert），其余一律保留。

  allowed_negative / null_policy / weighted / denominator / note。

  - `infer_metric_spec(FieldProfile)`：按字段名正则推断（库存余额→snapshot_last；
    满意度/评分/nps→mean；转化率/利润率/率→mean+未加权注释；订单数→count_distinct；

  - allowed_negative 指标若仍需结构视角，hint 带 `chart_override=share_bar` 走柱状对比。

## 五、T04 View/Probe 校验门禁

- `ValidationLevel = pass | warn | fail | no_data`；checks 新增 code `reconciliation`。
- `ViewExecutionResult`：
  - `validity` = 该 View 全部 checks 的最差级别；
  - `consumable = validity in {pass, warn}`（fail/no_data 不可消费）；
  - `passed` 保留为别名。
- executor `_checks`：
  - 参与行数取最后一个 filter 输出；零行 → coverage `no_data`（不再是"通过"）；
  - shape：全 NaN/Inf → fail；
  - share：新增 reconciliation（份额和≈1 → pass，否则 warn）。
- `dashboard_synthesizer.consumable_results()` 是 KPI / ChartSpec / Section /
  Finding / probe 的**唯一消费门禁**；无数据 KPI 直接跳过，绝不展示 0。
- ProbeRunner：零行/全空结果门禁并写 consumable，失败 probe 不阻断合成。

## 六、T05 可比时间与变化口径

- `schemas/period.py`：`PeriodSpec`（mode/granularity/timezone/四窗口端点/data_as_of/
  completeness/observed_days/expected_days），`ComparisonMode = mom|wow|yoy`。
- `services/period_compare.py`（算子、KPI、Finding 共享的唯一实现）：
  - `build_period_spec`：以 max(event_time) 为截至线索；naturally_ended 判定
    （月末日/满 7 天）；partial→等长 MTD 窗口；自然期已结束但缺日→unknown。
  - `compare_change`：prev>0 才有 growth_pct；率值用 change_pp；
    负基数给状态文案；零基数显式说明。
  - `period_comparison()`：缺对比期抛 `PeriodCompareError`（中文），
    当前期无有效数据返回 None（不造数）。
- 引擎 `op_period_compare` 改为薄封装；输出行标签为实际窗口
  （如 `2024-03-01 ~ 2024-03-25（截至日同期）`）。
- KPI 与趋势 Finding **不再直接拿趋势图最后两个聚合桶相除**（最后一桶可能残缺），
  统一在快照上调用 `period_comparison`；partial 时 KPI 带 hint
  "当期未结束，按截至日等长窗口比较"，Finding 文案标注窗口与口径。
