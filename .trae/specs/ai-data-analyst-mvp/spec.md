# AI Data Analyst MVP - 产品需求文档（PRD）

## Overview

- **Summary**：面向不会 SQL / Python 的普通业务用户的 AI 数据分析工作台。用户上传标准二维 CSV / Excel 数据后，在 AI 引导下经「语义确认 → 质量处理 → 问题推荐 → 方案确认 → 确定性计算 → 结果校验 → 可视化 → 洞察 → 追问」完成完整分析闭环。产品不做完整 BI，而是一套**可解释、可验证、可控**的 AI 分析工作流。
- **Purpose**：作为 AI 产品经理秋招作品集核心项目，集中展示两项能力：① AI Workflow 产品设计（十阶段引导式工作流、人工确认闸门、结构化交互）；② AI 可靠性与可控性设计（LLM 不碰数值、有限算子集、结构化契约、证据链、因果护栏、可信度分级）。
- **Target Users**：无技术背景的业务人员（销售运营、市场、供应链、客服等岗位），以及招聘方（作品集评审者，关注 AI 产品设计深度与工程严谨性）。

## Goals

- G1：在 5 份不同业务场景的真实感数据集上，稳定跑通十阶段完整分析闭环，无关键错误。
- G2：所有数值结果由确定性计算引擎产出，LLM 不执行任何数值计算；每条结论可追溯到数据范围、字段、筛选、公式与结果。
- G3：将「AI 不可靠」的典型风险（语义误判、自由生成代码、算错数、编造数字、相关性说成因果、低置信结论误导）逐一转化为用户可感知的产品机制（确认闸门、校验状态、证据抽屉、风险标签）。
- G4：极简 UI，用户注意力始终聚焦「问题 → 分析 → 图表 → 洞察 → 证据」主线。

## Non-Goals（第一版明确不做）

- 数据库连接、网页爬虫、API 数据接入、实时/流式数据。
- 复杂 Excel 能力：多 Sheet 关联、公式、透视表、合并单元格解析（仅读取首个工作表的单一二维表）。
- Dashboard / 报表拼装、定时报告、PDF/PPT 导出、告警订阅。
- 多人协作、账号体系、权限管理、云端部署（第一版仅本地单机运行）。
- 在线表格编辑、数据录入、行列自由变换（仅支持本文件定义的质量处理动作）。
- 自由文本代码（SQL/Python）生成与执行。
- 移动端原生适配（桌面浏览器优先，保证窄屏不错乱即可）。

## Background & Context

- 工作区为空目录，项目从零构建。
- 已确认技术决策：Next.js + FastAPI 双进程架构；LLM 通过 OpenAI 兼容接口接入，默认 DeepSeek（`base_url` 与 key 经 `.env` 配置，可切换任意兼容 provider）；内置 5 份埋有数据质量问题的示例数据集；数据质量模块做「检测 + 逐项确认处理」。
- 本机环境：Node v24 / npm 11；系统 Python 3.9，已安装 `uv`，后端使用 uv 管理 Python 3.11+ 虚拟环境。
- 核心设计命题：**LLM 负责「理解、规划、表达」，确定性引擎负责「算数」**。两者之间以经过校验的结构化契约通信，并由人工确认闸门兜底。

## 产品工作流（十阶段与状态机）

阶段按序推进，允许回退修改；每个阶段有明确的进入条件（闸门）：

| # | 阶段 | 关键产出 | 进入下一阶段的闸门 |
|---|---|---|---|
| 1 | Upload 上传 | 解析后的原始数据表 | 格式/大小/行列数校验通过 |
| 2 | Semantic Profile 语义分析 | 数据字典（字段语义档案） | 所有中/低置信字段经用户确认 |
| 3 | Data Quality 质量检测处理 | 质量报告 + 处理后数据快照 | 每条质量问题均有用户处理决策 |
| 4 | Question Recommendation 问题推荐 | 分类推荐问题 + 自定义问题 | 用户选中或提交一个问题 |
| 5 | Analysis Plan 分析方案 | 结构化分析方案 JSON | 用户确认或编辑后确认方案 |
| 6 | Execute 执行 | 计算结果 + 完整计算台账 | 引擎正常返回（异常即报错，禁止编造） |
| 7 | Validate 结果验证 | 校验项清单（pass/warn/fail） | 无 fail（warn 需用户知悉后继续） |
| 8 | Visualize 可视化 | 图表 + 结果表 | 自动呈现 |
| 9 | Insight 洞察 | 结构化洞察（内含洞察验证与可信度） | 洞察通过接地与因果校验 |
| 10 | Follow-up 追问 | 后续问题建议 | 用户选择追问（回到阶段 5）或结束 |

## 可靠性与可控性总体设计（三层防线 + 人工闸门）

1. **确定性计算层**：pandas 实现的计算引擎，只接受通过 schema 校验的分析方案 JSON，算子来自固定目录；未登记操作直接拒绝。引擎包内禁止出现 LLM 客户端调用。
2. **结构化契约层**：所有 LLM 输入/输出均为有 schema 的 JSON（语义档案、推荐问题、分析方案、洞察草稿、追问）。输出经解析 → 校验 → 有限自动修复（最多 2 次）→ 仍不合法则显式报错，**绝不静默编造、绝不猜测数值**。
3. **证据与护栏层**：每次执行产出计算台账（快照哈希、行范围、筛选、公式、中间结果）；每条洞察的数字必须与引擎结果逐一接地；观测性分析禁止因果表述；可信度按策略分级。
4. **人工确认闸门**：语义确认门、质量处理决策门、方案确认门；低可信洞察标注「需进一步验证」而非作为事实呈现。

## Functional Requirements

### FR-1 Upload 数据上传与解析

- 支持 `.csv` 与 `.xlsx/.xls`；Excel 仅读取首个工作表的单一二维表，首行为表头。
- 限制：文件 ≤ 20MB；数据行 ≤ 200,000；列数 ≤ 50；超出或格式不符给出明确中文错误，不进入后续阶段。
- 自动识别 CSV 编码（utf-8 / gbk / utf-8-sig）与分隔符；保留原始文件。
- 解析后展示：文件名、行列数、前 10 行预览、每列推断的原始数据类型。
- 内置 5 份示例数据集可一键载入（见附录 B）。

### FR-2 Semantic Profiler 语义分析器

- 先规则后模型：先用确定性规则推断 dtype、基数、数值范围（min/max/均值）、空值率、样例值、命名特征；再调用 LLM 在规则结果之上补全业务语义。
- 每个字段产出语义档案：字段名、物理类型、语义类型（dimension 维度 / metric 指标 / date 日期 / id 标识 / geo 地理 / unknown 待确认）、业务含义解释、单位（如元/个/%/秒）、候选业务含义列表、时间字段标识、指标字段标识、置信度（high/medium/low）、样例值。
- 确定性地探测字段关系线索（如「单价 × 数量 ≈ 金额」、高相关数值列对），供问题推荐使用。
- 确认机制：所有 medium/low 置信字段在界面上明确标黄，必须由用户从候选中选择、或自行输入含义、或选择「忽略该字段（不参与分析）」后才能继续；用户可修正任意 high 置信字段。确认结果写回数据字典并持久化。

### FR-3 Data Quality 数据质量检测与处理

- 检测四类问题，逐列/逐行给出证据（位置、样例、数量、占比）：
  - 缺失值；
  - 类型/格式异常（如 `"¥1,200"`、混写日期 `2024/1/3` 与 `2024-01-03`、`-1` 哨兵值、大小写不一致的枚举）；
  - 完全重复行；
  - 数值离群（IQR/Z-score 确定性判定，注明规则与阈值）。
- 每类问题提供**建议动作**与可选项，用户逐项决策：
  - 缺失：保留（计算时排除）/ 删除行 / 填充（固定值、均值、中位数、众数）；
  - 格式异常：接受系统转换（展示转换样例）/ 保留为文本；
  - 重复行：删除 / 保留；
  - 离群值：保留 / 标记（新增标记列）/ 排除。
- 所有决策记录入质量报告；基于决策生成「处理后数据快照」，后续一切计算只针对该快照；用户可回退修改并重新生成快照。

### FR-4 Question Recommender 智能问题推荐器

- 基于数据字典、字段关系线索与场景模板生成 6–10 个推荐问题，覆盖至少 4 个分类：总量概览、趋势、对比、占比、排名、异常、相关（按数据适配，日期字段缺失时不产生趋势类）。
- 每条推荐必须包含：问题文本、分类、**推荐依据（说明相关字段、数据特征或业务逻辑，非空且具体）**、涉及字段、对应的目标算子（用于预填规划器）、置信度。
- 分类展示；支持用户输入自定义问题（自由文本，进入规划器）；支持「换一批」重新生成。

### FR-5 Analysis Planner 分析方案规划器

- LLM 将问题翻译为结构化方案，**只能使用附录 A 的有限算子目录**；方案包含：问题复述、数据范围说明、有序步骤（算子 + 参数：字段、筛选、时间粒度、排序、Top N 等）、每步的人读公式描述、预期结果形态、图表类型提示。
- 方案经服务端 schema 校验：算子必须在目录内；引用字段必须存在于数据字典；参数类型/取值合法；时间类算子必须指定已确认的日期字段；不合法则有限自动修复（≤2 次），仍不合法则显式报错并允许用户重试或手动编辑。
- 方案以可视化步骤卡片展示（数据范围 → 筛选 → 分组/聚合 → 呈现），用户可调整：指标、分组维度、时间粒度、筛选条件、Top N；确认后锁定（记录方案哈希）。
- 严禁生成或执行任何自由代码（SQL/Python/表达式沙箱均不允许）。

### FR-6 Analysis Executor 分析执行器

- 基于锁定方案与质量处理后快照，用 pandas 逐步执行；LLM 不参与任何数值运算。
- 每次执行记录**计算台账**：会话/快照 ID、快照文件哈希、参与计算行数、每步（算子、参数、输入行数、输出形态、人读公式、中间结果摘要）、最终结果集、执行时间。
- 结果表界面最多展示 1,000 行并注明全量行数；图表使用全量聚合结果。
- 引擎错误（字段缺失、类型不符等）直接阻断并返回中文错误，不允许任何兜底编造。

### FR-7 Validate 结果验证（阶段 7）

- 在执行结果上运行确定性校验，每项输出 pass / warn / fail 与说明：
  - 覆盖率：实际参与行数 vs 快照行数，差额须能被筛选条件解释；
  - 交叉验算：如分组求和 == 总计、占比之和 == 100%（容差内）；
  - 空值处理：指标空值数量与处理方式明示；
  - 结果形态：无意外 NaN/Inf、百分比在合法区间；
  - 方案一致性：实际执行步骤与已确认方案哈希一致。
- 存在 fail 时阻断可视化与洞察；warn 需界面明示，用户知悉后方可继续。校验记录写入台账。

### FR-8 Visualize 可视化

- 图表类型由算子**确定性映射**（附录 A），不由 LLM 决定；图表数据仅取自引擎结果。
- 至少支持：指标卡、折线图、柱状图、条形图、占比图（条形/饼）、散点图、离群标注折线、明细表。
- 图表与结果表、人读公式同屏呈现；图表上方显示问题与数据范围。

### FR-9 Insight Generator 洞察生成器

- LLM 仅接收：方案的人读描述、引擎结果（聚合后、数值按展示精度）、校验状态、数据字典；不接收全量明细（小表除外）。
- 每条洞察为结构化对象：结论文本、类型（关键发现/趋势/对比/异常/风险提示）、证据引用（步骤/结果 ID 列表，≥1）、文本中出现的数字清单（数值 + 来源引用）、置信度与理由、是否需进一步验证。
- 卡片式简洁呈现，突出关键发现；每条洞察可展开**证据抽屉**：数据范围、相关字段、筛选条件、计算公式、实际结果值、校验状态。
- 一次分析默认生成 2–5 条洞察，宁缺毋滥。

### FR-10 Insight Validator 洞察验证器（阶段 9 内部门禁）

- **数字接地校验**：洞察文本中的每个数字都必须能在其引用的引擎结果中找到匹配值（按展示精度容差）；不匹配则拦截并重生成（计入有限修复次数）。
- **因果护栏**：对观测性/相关性分析，出现因果词表（如「导致、引起、使得、拉动、提升了、驱动、因果、because、cause、drive、lead to、due to」）一律拦截，要求改写为合规表述（如「与…相关、占比更高、同期相比…变化、伴随…出现」）。相关分析结论必须含「相关关系，不代表因果」提示。
- **证据完整性**：每条结论至少 1 个有效证据引用，且引用指向真实存在的结果。
- **统计方向一致性**：如相关系数正负号、同比升降方向必须与结果一致。
- **可信度策略**：数字全部接地 + 证据完整 + 校验通过 → high；涉及相关分析、样本量小、受离群值影响、存在 warn → 置信度封顶并标注「需进一步验证」；无法通过校验的洞察不展示给用户。

### FR-11 Follow-up 后续问题建议

- 基于已执行方案与结果生成 3–5 个追问建议（如下钻某维度、切换时间粒度、查看相关指标、异常项拆解），每条附推荐依据；点击后带上下文预填进入阶段 5。

### FR-12 会话与持久化

- 以会话为单位组织，所有产物（原始文件、处理后快照、数据字典、质量报告、推荐问题、方案、执行台账、洞察）落盘为可检视文件，便于作品集演示「AI 的每一步都留痕」。
- 支持刷新页面后恢复会话；支持重新生成单阶段产物（重新生成不影响已确认下游时给出提示）。

### FR-13 错误与降级哲学

- 任何 LLM 阶段契约校验失败、修复次数耗尽时：展示明确错误（所处阶段、原因、可操作建议），提供「重试 / 编辑输入」入口；严禁返回编造内容或用 LLM 自造数字兜底。
- 网络或 key 配置错误：在上传后第一次调用模型前给出可理解的配置指引。

## Non-Functional Requirements

- **NFR-1 性能**：20 万行规模下，常规单问题计算（筛选+分组聚合/时间聚合）引擎耗时 ≤ 5 秒（M 系列 Mac 基准）；LLM 阶段有加载态与阶段说明，单阶段超时 60 秒可重试。
- **NFR-2 安全**：不执行任何 LLM 生成的代码；上传文件按类型白名单校验并随机化存储名；LLM API key 仅存在于后端 `.env`，不下发前端；后端仅监听本地。
- **NFR-3 可测试性**：LLM 调用层支持「录制/回放」固件，全部自动化验收在无 API key、无网络条件下可重复运行。
- **NFR-4 兼容性**：最新版 Chrome / Safari / Edge 桌面端；中文界面。
- **NFR-5 工程质量**：后端关键模块（引擎、校验器、契约、护栏）具备单元测试；提供 5 数据集端到端黄金用例；前端通过类型检查与生产构建。
- **NFR-6 可观测（面向演示）**：关键 AI 阶段向用户展示「AI 正在做什么 / 依据是什么 / 是否通过校验」，而非黑盒转圈。

## Constraints

- **Technical**：前端 Next.js 14+（App Router、TypeScript、Tailwind、Recharts）；后端 FastAPI + pandas + Pydantic v2，Python 3.11+（uv 管理）；LLM 使用 OpenAI 兼容 SDK，默认 DeepSeek；单机双进程本地运行。
- **Business**：单人作品集项目，无预算压力但默认模型需低成本；范围严守 Non-Goals，不堆功能。
- **Dependencies**：DeepSeek API key（用户自备，写入后端 `.env`；无 key 时可用录制固件体验完整流程与运行全部自动化测试）。

## Assumptions

- 上传数据为首行表头的标准二维表；每列语义单一；日期列可被解析为公历日期。
- 单次分析问题在算子目录表达能力之内；超出能力的问题由规划器明确说明「当前版本不支持」，而非强行作答。
- 示例数据集由仓库脚本以固定随机种子生成，数值可被测试作为黄金断言。
- 评审/验收环境可能没有可用 API key，因此 5 数据集闭环验收以录制固件为准；真 LLM 冒烟测试在用户提供 key 后手动执行。

## 附录 A：有限分析算子目录（契约的一部分）

| 算子 ID | 含义 | 关键参数 | 确定性图表映射 |
|---|---|---|---|
| `filter` | 按维度/数值/日期范围筛选 | 字段、操作符、值 | 透传下游 |
| `aggregate` | 总量聚合：sum/mean/median/count/count_distinct/min/max | 指标列、聚合函数 | 指标卡 |
| `group_by` | 按维度分组聚合 | 维度、指标、函数、排序、limit | 柱状/条形图 |
| `share` | 各成员占总计比例 | 维度、指标 | 条形占比图/饼图 |
| `top_n` | 排名取前 N | 维度、指标、N、升降序 | 条形图 |
| `time_series` | 按日/周/月/季/年时间聚合 | 日期列、粒度、指标、函数 | 折线图 |
| `period_compare` | 同比/环比/周环比及增长率 | 日期列、周期、指标、函数 | 指标卡+对比柱 |
| `compare_groups` | 多组指标对比 | 维度、成员、指标、函数 | 分组柱状图 |
| `correlation` | 两数值列相关系数（Pearson/Spearman） | 两个指标列、方法 | 散点图 |
| `outlier_flag` | 序列离群检测并标注（IQR 或 z-score） | 指标列、规则、阈值 | 折线+离群标记 |

方案可由多个算子有序组合；除 `filter` 透传外，一个方案的末端算子决定图表类型。算子目录以外的任何操作、任何自由代码均视为非法方案。

## 附录 B：5 份内置示例数据集

## Acceptance Criteria

### AC-1：上传边界与解析正确性
- **Type**: `rule`
- **Given**：用户在上传页选择文件
- **When**：上传合法 CSV/XLSX（≤20MB、≤200,000 行、≤50 列）或超限/不支持格式的文件
- **Then**：合法文件成功解析并展示行列数与前 10 行；非法请求被拒绝并显示具体中文原因（格式、大小、行数、列数）
- **Pass Condition**：参数化测试覆盖 CSV(utf-8/gbk)、XLSX、超大小、超行数、超列数、非二维/非白名单后缀，结果均符合预期
- **Evidence**：后端单元测试 + API 测试结果；前端界面截图

### AC-2：语义档案与人工确认闸门
- **Type**: `rule`
- **Given**：文件解析完成
- **When**：系统生成字段语义档案
- **Then**：每字段包含物理类型、语义类型、业务解释、候选含义、样例值、置信度；所有 medium/low 字段在 UI 标黄且未全部确认时无法进入下一阶段；用户选择候选/自定义/忽略后结果持久化到数据字典
- **Pass Condition**：① 5 份数据的字段语义类型识别经固件断言（日期列、指标列、id 列正确）；② 前端在存在未确认字段时「下一步」禁用；③ 忽略的字段不出现在后续算子可选字段中
- **Evidence**： profiler 规则测试、契约固件测试、前端状态测试/截图、落盘数据字典 JSON

### AC-3：数据质量检测、逐项决策与快照
- **Type**: `rule`
- **Given**：数据字典已确认
- **When**：运行质量检测并由用户对每条问题做出处理决策
- **Then**：四类问题（缺失/格式异常/重复/离群）均带证据与建议动作；未全部决策不能继续；按决策生成处理后快照且效果可验证（如删除重复行后行数正确、货币串转为数值）；决策与快照哈希写入质量报告
- **Pass Condition**：在 5 份预埋问题数据上，各类问题均被检出且数量与预埋一致；每种处理动作有单元测试断言快照结果；决策记录可在落盘 JSON 中检视
- **Evidence**：质量检测测试、处理动作测试、质量报告 JSON、前端截图

### AC-4：推荐问题的分类、依据与自定义
- **Type**: `rule`
- **Given**：质量快照已生成
- **When**：请求问题推荐
- **Then**：返回 6–10 个问题，至少覆盖 4 个分类；每条含非空且具体的推荐依据（引用具体字段/数据特征/场景逻辑）、涉及字段与目标算子；无日期字段的数据不产生时间趋势类问题；自定义问题可提交并进入规划
- **Pass Condition**：契约测试断言字段完整性与分类数量；固件测试断言每条 rationale 非空且包含至少一个字典字段名或明确特征词；无日期数据集（构造用例）不返回时间类推荐；自定义问题端到端可达方案页
- **Evidence**：推荐器契约测试、前端截图

### AC-5：有限算子方案的生成、校验与确认
- **Type**: `rule`
- **Given**：用户选定或输入问题
- **When**：生成分析方案
- **Then**：方案仅使用附录 A 算子；服务端拒绝未知算子、不存在字段、非法参数（含时间算子无日期字段）；非法 LLM 输出在 ≤2 次修复后仍失败时显式报错；UI 以步骤卡展示数据范围/筛选/公式并支持编辑与确认；确认后锁定方案哈希
- **Pass Condition**：① 方案 schema 校验单测（含 3 类非法输入）；② 代码库中不存在任何执行 LLM 自由代码的路径（eval/exec/sql 执行点审计）；③ 前端编辑指标/维度/粒度/筛选后方案 JSON 同步更新；④ 确认后执行的实际方案哈希一致（与 AC-8 联动）
- **Evidence**：schema 校验测试、代码审计结论、前端截图、方案 JSON

### AC-6：LLM 不进行任何数值计算
- **Type**: `rule`
- **Given**：全代码库
- **When**：审计计算路径与 LLM 交互边界
- **Then**：所有数值结果只能由计算引擎模块产出；引擎模块不依赖/不导入 LLM 客户端；LLM 提示词与输出中不出现「可信结果数值」——洞察中的数字必须以引擎结果为唯一来源并经接地校验
- **Pass Condition**：静态检查（引擎目录无 LLM 依赖）+ 契约测试（方案/洞察 LLM 固件中的数字若与引擎结果不一致必被拦截，含人为篡改固件的负例）
- **Evidence**：依赖关系审计、接地校验负例测试

### AC-7：确定性执行与完整计算台账
- **Type**: `rule`
- **Given**：方案已确认
- **When**：引擎执行
- **Then**：逐步产出 pandas 计算结果，并落盘台账：快照 ID/哈希、参与行数、每步算子/参数/输入行数/输出形态/公式/中间结果摘要、最终结果、耗时；引擎错误以中文错误阻断，无兜底数值
- **Pass Condition**：每个算子有独立正确性单测（含手算黄金值）；执行后端台账 JSON 字段齐全且快照哈希与实际文件一致；错误输入返回错误而非结果
- **Evidence**：算子单测、台账 JSON 样例、错误路径测试

### AC-8：结果验证闸门
- **Type**: `rule`
- **Given**：一次执行完成
- **When**：运行结果校验
- **Then**：覆盖率、交叉验算、空值处理、结果形态、方案一致性五项均给出 pass/warn/fail；fail 阻断后续阶段；warn 在 UI 明示并记录用户知悉
- **Pass Condition**：单测构造各类 fail/warn 场景（筛选掉行、分组和≠总计、意外 NaN、方案被篡改）验证判定与阻断逻辑
- **Evidence**：校验器单测、前端阻断行为截图

### AC-9：洞察证据链可追溯
- **Type**: `rule`
- **Given**：通过校验的分析结果
- **When**：生成并展示洞察
- **Then**：每条洞察可展开证据抽屉，完整展示数据范围、相关字段、筛选条件、计算公式、实际结果值、校验状态；证据引用真实指向台账中的步骤/结果
- **Pass Condition**：UI 逐项核对 6 类证据信息齐备；点击证据可定位到对应台账记录；E2E 固件中每条洞察 evidenceRefs 非空且可解析
- **Evidence**：E2E 测试断言、前端证据抽屉截图

### AC-10：因果表述护栏
- **Type**: `rule`
- **Given**：观测性/相关性分析结果
- **When**：LLM 产出含因果表述的洞察，或产出合规表述
- **Then**：因果词表命中即拦截并要求改写（计入修复次数）；相关分析结论强制附带「相关关系，不代表因果」；合规表述正常通过
- **Pass Condition**：构造 ≥10 条正/负例（中英因果词、合规替代表述、非观测性语境豁免）单测判定全部正确
- **Evidence**：护栏单测、拦截记录

### AC-11：洞察数字接地
- **Type**: `rule`
- **Given**：洞察文本与其引用结果
- **When**：校验文本中的数字
- **Then**：每个数字均能以展示精度在引用结果中匹配；人为加入未接地数字（如把 12.3% 改成 13.2%）的洞察必被拦截
- **Pass Condition**：接地校验正/负例单测通过；E2E 中所有展示洞察通过接地
- **Evidence**：接地校验测试、E2E 断言

### AC-12：可信度分级与风险标注
- **Type**: `rule`
- **Given**：洞察通过结构校验
- **When**：按策略计算置信度
- **Then**：全接地+证据完整+无 warn → high；相关分析/小样本/离群影响/存在 warn → 按规则封顶为 medium/low；low 在 UI 明确标注「需进一步验证」
- **Pass Condition**：策略单测覆盖各降级条件；5 数据集 E2E 中每条洞察的置信度与触发条件可在 JSON 中复核
- **Evidence**：策略单测、洞察 JSON、前端标签截图

### AC-13：5 份数据集端到端闭环稳定性
- **Type**: `rule`
- **Given**：附录 B 的 5 份示例数据与录制好的 LLM 固件
- **When**：以自动化方式从 Upload 逐阶段运行至 Follow-up
- **Then**：5 份数据均完成十阶段、无关键错误；每份至少完成 1 个推荐问题的完整分析，产出通过校验的图表与 ≥1 条洞察；关键聚合数值与黄金值一致；追问可再次进入规划
- **Pass Condition**：离线（无 key/无网络）E2E 套件全部通过
- **Evidence**：pytest E2E 输出、5 份数据的会话产物目录

### AC-14：后续追问与回流
- **Type**: `rule`
- **Given**：洞察已生成
- **When**：请求追问建议
- **Then**：返回 3–5 条追问且每条附依据；点击任一追问可带原会话上下文进入方案页并预填问题
- **Pass Condition**：契约测试数量/依据完整性；E2E 模拟点击回流并成功生成方案
- **Evidence**：契约测试、E2E 日志

### AC-15：契约失败的显式降级
- **Type**: `rule`
- **Given**：LLM 返回畸形 JSON 或 schema 不符内容
- **When**：发生在任一 AI 阶段
- **Then**：系统最多自动修复 2 次，仍失败则界面显示阶段、原因与重试/编辑入口；任何阶段不出现编造结果或假数字
- **Pass Condition**：以畸形固件模拟 5 个 AI 阶段，断言错误信息与重试入口，且会话中无结果被伪造
- **Evidence**：负例契约测试、前端错误态截图

### AC-U1：极简工作流界面质量
- **Type**: `rubric`
- **Dimension**：界面是否让无技术用户始终清楚「我在哪一步、AI 在做什么、我该确认什么、结论依据是什么」，且视觉极简
- **Scale**: 1-5
- **Anchors**：1 = 流程混乱、AI 黑盒、信息堆砌；3 = 流程可走通但阶段感与证据呈现一般；5 = 十阶段清晰可导航，确认闸门/校验状态/证据抽屉自然融入，「问题→分析→图表→洞察→证据」主线突出，视觉克制统一
- **Pass Threshold**: ≥ 4
- **Evidence**：5 份数据完整走查截图、评审者（独立 Review 子代理）按维度打分

### AC-U2：AI 可靠性与可控性的产品化表达
- **Type**: `rubric`
- **Dimension**：六项核心风险（语义误判、脏数据、自由代码、算错数、编造数字、因果误导）是否都转化为用户可见、可操作的产品机制，而非仅停留在代码层
- **Scale**: 1-5
- **Anchors**：1 = 机制缺失或仅工程内部可见；3 = 主要风险有处理但用户感知弱；5 = 每项风险均有对应可见机制（确认门、逐项决策、算子白名单、校验状态、证据抽屉、因果提示、可信度标签），形成完整可信叙事
- **Pass Threshold**: ≥ 4
- **Evidence**：产品走查 + 机制-风险对照表（独立 Review 打分）

### AC-U3：工程可维护性与演示稳定性
- **Type**: `rubric`
- **Dimension**：代码结构、测试组织、启动成本与离线可演示性
- **Scale**: 1-5
- **Anchors**：1 = 结构混乱、无法离线复现；3 = 可运行但分层不清或依赖在线调用；5 = 前后端分层清晰（契约/引擎/护栏独立），一条命令装依赖、一条命令跑测试，固件回放可完整离线演示
- **Pass Threshold**: ≥ 4
- **Evidence**：目录结构、测试运行输出、独立 Review 打分
